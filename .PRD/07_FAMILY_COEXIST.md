## 4. 🆕 SessionStart 훅 규약 (신설 — 정본에 없는 공백 지대)

### 왜 신설이 필요한가

정본 §3에는 **PreToolUse·Stop·PostToolUse 규약만** 있고 **SessionStart 규약이 없습니다.**

**2026-08-02 실측: 6형제 전부 SessionStart hook 0개.** 즉 소담그래프엔지니어링이 **최초 사용자**입니다.

지금 계약을 만들지 않으면, 나중에 8·9번째 형제가 같은 자리를 쓰면서 싸웁니다. **그걸 막는 게 이 프로젝트의 목적**이므로, 자기가 먼저 무계약 상태로 들어갈 수 없습니다.

### 정본 §3 규약 A의 논리를 그대로 승계

> 정본: *"훅은 **병렬 실행** (순서 미보장). 6개가 모두 새 훅을 등록하면 확인창 6개 연속 → 초보자 permission fatigue → 그냥 허용 → 안전 무력화"*

SessionStart도 **동일한 병렬 실행 구조**입니다. 6형제가 각자 출력하면 **세션 시작이 안내문으로 뒤덮여** 사용자가 전부 꺼버립니다. 그러면 도구가 죽습니다.

### 규약 E — SessionStart 출력 예산

| # | 규칙 | 값 |
|---|-----|-----|
| E1 | 형제 1개당 출력 | **3줄 이내** |
| E2 | 패밀리 전체 합계 상한 | **10줄** (초과 시 형제 간 재조정) |
| E3 | 끄는 법 제공 | **필수** (`SODAM_GRAPH_SILENT=1`) |
| E4 | 침묵 조건 | 형제 저장소 밖에서 세션을 열면 **아무것도 출력 안 함** |
| E5 | **성능 예산** | **1초 이내.** 초과하면 `snapshot.json` 캐시만 읽고 백그라운드 재스캔 |
| E6 | 실패 시 | **조용히 침묵** (세션 시작을 절대 막지 않음) |

**E5가 중요한 이유**: `search_roots` 아래에 **60개 이상의 프로젝트 폴더**가 있습니다(실측). 매 세션 60곳에 git 명령을 돌리면 모든 세션이 느려지고, 사용자는 통증 ②를 풀려던 기능 때문에 도구를 끕니다.

| `logSafetyEvent(event)` | Harness | Reverse.SafetyLog, Loop.grader | 계획됨 |

**`isFamilyAlive(name)` 은 "형제가 살아있고 어디 있는가"를 답하는 함수입니다.**
소담그래프엔지니어링의 `lib/resolve.mjs` 가 **정확히 그 문제**를 풉니다 — `repo_remote` → `markers` → `lost` 3단계.

> 정본 §3 규약 D는 현재 `isHarnessAlive()` 가 **"파일 존재만 확인"** 해서 *"껍데기·깨진 Harness에 위임하면 무방비가 되는 fail-open"* 위험을 경고합니다.
> **소담그래프엔지니어링의 resolve 는 파일 존재가 아니라 `repo_remote` 대조로 확인**하므로 그 fail-open을 구조적으로 줄입니다.

### 발행 계약 (신규)

```
data/graph.json          정본 — 소담그래프엔지니어링만 씀 (자기 저장소)
        │
        └─ 요약 발행 ─▶  ~/.sodam/graph-state.json   ← 6형제 누구나 읽기 전용
```

| 항목 | 규정 |
|------|------|
| 쓰는 쪽 | **소담그래프엔지니어링 단독** |
