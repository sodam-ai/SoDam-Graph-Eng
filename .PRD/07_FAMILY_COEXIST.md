지금 계약을 만들지 않으면, 나중에 8·9번째 형제가 같은 자리를 쓰면서 싸웁니다. **그걸 막는 게 이 프로젝트의 목적**이므로, 자기가 먼저 무계약 상태로 들어갈 수 없습니다.

### 정본 §3 규약 A의 논리를 그대로 승계

> 정본: *"훅은 **병렬 실행** (순서 미보장). 6개가 모두 새 훅을 등록하면 확인창 6개 연속 → 초보자 permission fatigue → 그냥 허용 → 안전 무력화"*

SessionStart도 **동일한 병렬 실행 구조**입니다. 6형제가 각자 출력하면 **세션 시작이 안내문으로 뒤덮여** 사용자가 전부 꺼버립니다. 그러면 도구가 죽습니다.

#### 형제가 그대로 붙여 쓰는 조각 (의존성 0개)

```js
// ~/.sodam/graph-state.json 읽기 — 규약 F 준수 (SoDam-Graph-Eng 제공)
import { readFileSync } from 'node:fs';
import { homedir } from 'node:os';
import { join } from 'node:path';

export function readFamilyState() {
  try {
    const s = JSON.parse(readFileSync(join(homedir(), '.sodam', 'graph-state.json'), 'utf8'));
    if (s.version !== 1) return null;                       // F6
    const ageMin = (Date.now() - new Date(s.scanned_at).getTime()) / 60000;
    return { projects: s.projects, stale: ageMin > 60, ageMin };  // F5
  } catch { return null; }                                   // F3·F4 — 조용히 넘어감
}

// 쓰는 예: 형제 위치를 경로 하드코딩 없이 알아내기
const st = readFamilyState();
const loop = st?.projects.find(p => p.id === 'sodam-loop-eng');
if (loop?.resolve_status?.startsWith('found')) { /* loop.repo_root 사용 */ }
```

> 🔴 **`new Date(...)` 은 로컬 시각으로 해석됩니다.** 발행 쪽이 `toISOString()`(UTC)을 쓰면 **9시간 어긋납니다** — 소담그래프엔지니어링이 M4에서 실제로 겪은 버그 3건이 전부 이 원인이었습니다. 발행은 **로컬 시각 문자열**로 통일합니다.

#### 이 계약이 채우는 정본의 빈칸

정본 §4가 **"공통 표준화 필요 · 미구현"** 으로 비워둔 `isFamilyAlive(name)` 이 이것으로 채워집니다.

```js
export function isFamilyAlive(id) {
  const p = readFamilyState()?.projects.find(x => x.id === id);
  return !!p && p.resolve_status.startsWith('found');   // 파일 존재가 아니라 remote 대조 결과
}
```

> 정본 §3 규약 D가 경고한 *"파일 존재만 확인하는 `isHarnessAlive()` 의 fail-open"* 을, **`repo_remote` 대조 결과를 넘겨받는 방식**으로 구조적으로 줄입니다.
