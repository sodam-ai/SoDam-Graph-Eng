> 사용자가 가장 아프다고 한 문제 — "이미 테스트/검증은 끝났는데 계속 그자리에 머문다" — 만 다룹니다.

## 0. 왜 이 문서가 따로 필요한가

초안(2026-08-02 1차)에는 이 규격이 없었고, 정체 해소가 Phase 2로 밀려 있었습니다. 검토 결과 **초안 설계로는 정체가 안 풀린다**는 논리적 결함이 나와 규격을 신설하고 Phase 1으로 끌어올렸습니다.

### 초안의 결함 (자기 참조 함정)

```
초안:  verified (테스트 통과)  →  사람이 done_when 확인  →  done
```

사용자가 아픈 이유가 **바로 그 확인을 안 하는 것**입니다.
그래프는 "M4가 verified입니다"라고 말할 뿐이고, 확인이 여전히 안 되면 **그래프에도 verified로 영원히 남습니다.**

**정체가 `CHECKPOINT.md` 에서 `graph.json` 으로 자리만 옮깁니다. 문제를 옮겨 적기만 한 설계였습니다.**

증거: 초안 `01_PRD.md §5` 성공 기준 6개가 전부 "표시된다 / 맞춘다"였고, **"정체가 줄었다"를 재는 항목이 하나도 없었습니다.** 목적을 측정하지 않는 성공 기준은 성공 기준이 아닙니다.

## 1. 규칙 A — 기본값을 뒤집는다 (침묵 = 진행)

| | 누가 움직여야 하나 | 아무도 안 하면 |
|---|---|---|
| **초안** | 사람이 "됐다"고 해야 `done` | **영원히 멈춤** ← 정체 |
| **개정** | 기계가 `done` 후보로 올림, **사람은 "아니오"만** | **진행됨** |

### 근거

Anthropic 공식 에이전트 설계 패턴 중 **Evaluator–Optimizer** (`RESEARCH_SOURCES.md` §2-2) — 검증기가 판정하고 되돌아가는 루프이지, **사람의 승인을 기다리는 구조가 아닙니다.** 초안은 이 패턴을 조사해놓고 반대로 설계했습니다.

### 자동 승격 조건 (Phase 1 — 증거 기반, 실행 없음)

`verified` 인 마일스톤이 **아래 조건을 만족하면** `done_candidate` 로 올립니다.

> 🔴 **필수 조건 (2026-08-02 강화)**: **`E1` 또는 `E2` 중 최소 1개**가 반드시 포함돼야 합니다. 그 위에 보조 증거 1개 이상.
> 즉 **"아무거나 2개"가 아니라 "실물 증거 1개 + 보조 1개"** 입니다.

| # | 증거 | 종류 | 확인 방법 (읽기 전용) |
|---|------|------|---------------------|
| **E1** | `done_when` 에 적힌 파일이 실제로 존재 | **실물 (필수 후보)** | 파일 존재 확인 |
| **E2** | `evidence` 의 커밋 해시가 실재 | **실물 (필수 후보)** | `git -C <repo_root> cat-file -e <hash>` |
| E3 | 그 마일스톤 이후 커밋이 1개 이상 | 보조 | `git log` |
| E4 | `verified` 로 바뀐 지 7일 이상 | 보조 | `last_moved_at` 계산 |
| E5 | 열린 `Blocker` 가 없음 | 보조 | `Blocker` 조회 |

#### 왜 `E1|E2` 를 필수로 만들었나 (2026-08-02 강화 근거)

초안은 **"아무 증거 2개"** 였습니다. 그러면 `E3`(이후 커밋) + `E4`(7일 경과) 만으로 자동 승격이 됩니다.

**그런데 `E3` 은 오타 수정 커밋 하나로도 성립합니다.**

그리고 이 환경은 **다른 세션이 무관한 커밋을 수시로 넣습니다** — 2026-08-02 02:40에 실제로 관측됐습니다(소담에이전틱엔지니어링 커밋 2건, 소담하네스엔지니어링 4파일 145줄, 소담리버스엔지니어링 CHECKPOINT 수정).

즉 **안 끝난 일이 자동으로 `done` 처리될 확률이 높았습니다.**

> **정체(안 끝남)를 고치려다 반대편 실패(끝났다고 착각)를 만드는 건 더 나쁩니다.**
> 잘못된 완료는 **발견이 늦고 되돌리기 어렵습니다.** 그래서 실물 증거를 필수로 못 박았습니다.

#### 되돌리기 경로 2개 (둘 다 필요)

| 명령 | 시점 | 결과 |
|------|------|------|
| `/graph-reject <id>` | 승격 **전** (`done_candidate` 상태) | `verified` 로 복귀 + `rejected.json` 기록 → 재제안 안 함 |
| **`/graph-undo <id>`** ★신규 | 승격 **후** (`done` 상태) | `verified` 로 복귀 |

**`/graph-undo` 가 없으면**, "다음 스캔에서 done 처리"라는 시간차 때문에 **지나간 뒤 되돌릴 방법이 없습니다.**

### 출력 형식 (사람이 거부하기 쉽게)

```
[done 승격 제안]  소담프롬프트엔지니어링 · M7 기능 QA
  근거: E1 파일 존재 O / E2 커밋 실재 O / E4 verified 21일 경과 O
  → 아니라고 말씀 안 하시면 다음 스캔에서 done 처리합니다.
     되돌리려면: /graph-reject sodam-prompt-eng.M7
```

> **핵심**: 사람에게 "확인해 주세요"라고 **묻지 않습니다.** 통보하고, 틀렸을 때만 개입받습니다.
> 물어보면 안 하니까 정체된 것이므로, 묻는 설계는 같은 실패를 반복합니다.

### 안전장치

- 승격은 `graph.json` **정본에만** 기록. 형제 저장소는 그대로 (읽기 전용 불변)
- `data/rejected.json` 에 거부 이력을 남겨 **같은 항목을 다시 제안하지 않음**
- `owner: "human"` 이고 `Blocker.kind` 가 `legal` / `purchase` / `external_account` 면 **자동 승격 제외** (사람만이 할 수 있는 일이라 기계가 판단하면 안 됨)

## 3. 규칙 C — 하나만 지목한다 (임계 경로)

### 문제

`/graph-next` 는 7형제 각각의 다음 할 일을 알려줍니다. 그런데 **7개를 동시에 보면 결국 아무것도 안 합니다.** 지금 상태(6형제 중 5개 동시 정지)가 정확히 그 증상입니다.

### 해법 — `/graph-why` 는 딱 하나만 말한다

🔴 **실행 순서가 고정입니다. 이 순서가 아니면 무한 루프에 빠집니다.**

```
1단계  순환 탐지        depends_on 엣지에서 사이클을 먼저 찾는다
2단계  사이클 경고·제외   순환이 있으면 최우선 경고 + 그 노드는 점수 계산에서 뺀다
3단계  점수 계산        점수 = 정지 일수 × (1 + 막고 있는 형제 수) × 신뢰도
```

**왜 순서가 중요한가**: "막고 있는 형제 수"는 `Edge.depends_on` 을 **역추적**해서 셉니다. 순환이 있으면 **역추적이 끝나지 않습니다.** 순환 탐지가 같은 명령 안에 있어도 **뒤에 있으면 도달하지 못합니다.**

#### 🆕 신뢰도 계수 — `coarse` 형제를 빼면 안 되는 이유

| `state` | 신뢰도 | 출력 표기 |
|---------|-------|----------|
| 상세 있음 (`todo`~`done`) | **1.0** | 그대로 |
| **`coarse`** (상세 미상) | **0.7** | **`(상세 미상 — 추정치)`** 를 함께 표시 |

**왜 0.7이고, 왜 아예 빼면 안 되는가:**

2026-08-02 실측 기준 **7형제 중 3개가 `coarse` 예상**입니다 — 소담하네스엔지니어링 · 소담루프엔지니어링(둘 다 추적 파일 0개) · 소담에이전틱엔지니어링(마일스톤 구조 없는 날짜 로그형).

그런데 **가장 오래 멈춘 소담루프엔지니어링이 정확히 `coarse` 입니다.**

- **빼면**: 43%를 못 보는 임계 경로가 되고, `/graph-why` 가 **"지금 이걸 푸세요"라는 정답을 못 냅니다**
- **그냥 넣으면**: 상세를 모르면서 확신하게 됩니다

**계수 + 표기**가 둘 다 피하는 유일한 방법입니다. 0.7은 임의값이므로 **2주 운영 후 재평가**합니다 (지목이 실제로 맞았는지로 판정).

> 이 결정으로 `02_DATA_MODEL.md` 의 미결 항목 *"`coarse` 를 점수에 포함할지"* 가 해소됩니다.

### 출력 예시

> 🔴 **아래 수치(34일 등)는 2026-08-02 01:40 기준의 가상 예시이며, 13:30 재실측에서 무효가 됐습니다**(소담루프엔지니어링은 오늘 커밋 있음).
> **규격으로 지켜야 하는 것은 *계산식과 출력 형태*이지 수치가 아닙니다.** 구현할 때 이 숫자를 하드코딩하지 마십시오.
> 실행 시에는 `snapshot.json` 의 **정체 축 `days_in_state`** 를 씁니다 — 활동 축(`days_since_activity`)을 쓰면 오늘처럼 커밋이 잦은 날 **전원 0일이 되어 순위가 안 나옵니다** (`02` §Snapshot).

```
[지금 딱 하나만 푼다면]  소담루프엔지니어링 · M4        [02:40 기준]

  이유:
   · 34일 정지 (7형제 중 최장)
   · 이 형제가 막고 있는 것: 소담그래프엔지니어링 Phase 2.5
   · 점수 34 × (1+1) × 0.7 = 47.6   (상세 미상 — 추정치)
     2위 소담하네스엔지니어링  6 × (1+0) × 0.7 = 4.2  보다 11배

  다음 할 일: 실사용_테스트_가이드.md 5종을 새 세션에서 실행
  걸린 것: 사람 몫 (human_test) — AI가 대신 못 함
```

> **계산이 공식과 정확히 맞는지 확인하십시오.** 이 예시는 4차 개정에서 신뢰도 계수(×0.7)가 도입됐는데 **예시만 옛 공식(`34 × 2 = 68`)으로 남아 있었습니다.**
> 두 형제 모두 `coarse` 라 0.7이 곱해지고, 소담루프엔지니어링은 1명을 막고 있어 `(1+1)`, 소담하네스엔지니어링은 막는 형제가 없어 `(1+0)` 입니다.
> **출력 예시는 규격의 일부입니다** — 구현 AI가 예시를 보고 만들기 때문에, 예시가 공식과 어긋나면 코드도 어긋납니다.

### 순환 탐지 (이 기능이 반드시 있어야 하는 이유)

**초안 설계에 실제로 순환이 있었습니다.**

```
Phase 2 (정체를 푸는 계획)
  └→ 소담루프엔지니어링 완성에 의존
       └→ 소담루프엔지니어링은 가장 오래 정지
            └→ 그걸 풀려면 정체 해소 도구가 필요
                 └→ 그게 Phase 2  ← 처음으로
```

사람이 이걸 못 봤고, 그래프로 그렸으면 즉시 보였을 문제입니다. 그래서 M16(루프 연결)을 Phase 2.5로 격리했습니다 (`03_PHASES.md` 참조).

`/graph-why` 는 `depends_on` 엣지에서 **순환이 발견되면 최우선으로 경고**합니다. 순환이 있으면 그 계획은 영원히 안 끝나기 때문입니다.

> **이 기능 하나가 "그래프"라는 이름을 정당화합니다.** 이게 없으면 이 도구는 표 한 장으로 대체됩니다.

## 3-B. 규칙 D — 동시 세션을 전제한다 (2026-08-02 02:42 실증)

> 📌 **번호가 `3-B` 인 이유**: 규칙 A·B·C 확정 후 실측으로 추가된 항목이라 뒤에 붙었습니다.
> `4`로 재번호하지 않는 이유는 `01`·`03`·`04` 가 이미 **`06 §3-B` 로 참조**하고 있어, 번호를 바꾸면 참조 3곳을 동시에 고쳐야 하고 **거기서 새 불일치가 생기기 때문**입니다. 번호는 라벨일 뿐이므로 그대로 둡니다.

### 이 위험은 추정이 아니라 관측된 사실입니다

이 PRD를 작성하던 **바로 그 시간에**, 다른 Claude Code 세션이 형제들을 동시에 고치고 있었습니다.

| 형제 | 관측된 변화 | 시각 |
|------|-----------|------|
| 소담에이전틱엔지니어링 | 커밋 2개 신규 (`a5e0b2c`, `9415a09`) | 02:40 |
| 소담하네스엔지니어링 | `guard.mjs`·`_selftest.mjs`·`CHECKPOINT.md`·`CHANGELOG.md` 4파일 145줄 | 02:32~02:41 |
| 소담리버스엔지니어링 | `CHECKPOINT.md` 수정 | 02:39 |

01:40 실측에서는 "5형제가 6일째 정지"였는데, **한 시간 뒤 3형제가 움직이고 있었습니다.**

사용자가 말한 **"세션을 바꾸거나 여러 개를 키고 작업할건데 이런 과정이 반복될 거 같다"** 가 정확히 이것입니다.

### 이것이 깨뜨리는 것

- `snapshot.json` 은 **스캔 순간의 사진**입니다. 다른 세션이 커밋하면 **즉시 낡습니다**
- 낡은 스냅샷으로 "34일 정지"라고 말하면 **틀린 지목**이 되고, 틀린 지목이 반복되면 사용자가 `/graph-why` 를 믿지 않게 됩니다
- 신뢰를 잃은 판정 도구는 정체를 못 풉니다

### 규칙

| # | 규칙 | 이유 |
|---|-----|------|
| D1 | **모든 판정 출력에 스캔 시각을 붙인다** (`02:40 기준`) | 사용자가 낡았는지 스스로 판단 가능 |
| D2 | **스냅샷이 10분 이상 오래되면 자동 재스캔** 후 판정 | 오래된 사진으로 지목하지 않음 |
| D3 | **`done` 자동 승격 직전에 해당 형제만 재스캔** | 승격은 되돌리기 번거로우므로 최신 상태에서만 |
| D4 | 스캔 도중 형제의 `HEAD` 가 바뀌면 **그 형제만 다시 읽는다** | 스캔 중 커밋이 들어오는 경우 |
| D5 | **`graph.json` 정본에 쓸 때 파일 잠금** (`data/.lock`) | 두 세션이 동시에 승격하면 정본이 깨짐 |

> D5가 없으면 여러 세션이 같은 `graph.json` 을 동시에 고쳐 **그래프 자체가 손상**됩니다. Phase 1 M11에 포함합니다.
